# Проверка на двух устройствах

Пошаговая инструкция, как проверить Porta вживую. Всё, что здесь написано, проверено на
macOS 09.09.2026 — кроме отмеченного как «не проверял».

## Порядок: сначала проверка, потом упаковка

Упаковка (установщики, подпись) — большая работа, и делать её **до** живой проверки
рискованно: если обнаружится, что mDNS не проходит через реальную сеть или QUIC режет
файрвол, придётся переделывать. Проверка при этом почти ничего не требует.

## Шаг 0 (5 минут): два экземпляра на одной машине

Быстрая проверка, которая ловит грубые ошибки до того, как вы пойдёте за вторым
компьютером. Экземпляры делят машину, поэтому им нужны **разные папка данных и порт** —
иначе это одно и то же устройство с одной личностью и одним портом.

```bash
PORTA_DATA_DIR=/tmp/porta-a PORTA_PORT=47101 dotnet run --project src/Porta.App.Desktop
```

Во втором терминале:

```bash
PORTA_DATA_DIR=/tmp/porta-b PORTA_PORT=47102 dotnet run --project src/Porta.App.Desktop
```

Проверено: получаются два разных Device ID, оба объявляются в сети. Убедиться со
стороны системы можно так — должно показать две записи:

```bash
dns-sd -B _porta._tcp local
```

**Чего этот шаг НЕ проверяет:** передачу между разными машинами, файрвол, работу через
Wi-Fi, поведение на других ОС. Это репетиция, а не проверка.

## Шаг 1: подготовить вторую машину

Вариант А — если на второй машине есть .NET 10 SDK: скопировать репозиторий и запускать
`dotnet run`, как на первой.

Вариант Б (проще для не-разработчика) — собрать самодостаточную папку и скопировать:

```bash
dotnet publish src/Porta.App.Desktop -c Release -r osx-arm64 --self-contained true -o ~/porta-mac
```

Получается ~116 МБ, .NET на второй машине не нужен. Для других целей подставьте
`-r win-x64` или `-r linux-x64`.

**libmsquic.** Без неё QUIC не работает и синхронизация молча не идёт.
- macOS: копия `libmsquic.dylib` кладётся в папку публикации автоматически
  (`Directory.Build.targets`). Проверено: файл в публикации есть.
- Windows: msquic входит в состав .NET — отдельно ставить не нужно (*не проверял*).
- Linux: нужен пакет `libmsquic` из репозитория Microsoft (*не проверял*).

## Шаг 2: сеть

Обе машины — в одной сети, и сеть не должна изолировать клиентов друг от друга
(на гостевом Wi-Fi и в некоторых корпоративных сетях mDNS и прямые соединения
заблокированы — там ничего не заработает, и это не дефект приложения).

Нужно пропустить: **UDP 5353** (mDNS) и **UDP 47100** (QUIC).

macOS при первом запуске спросит про входящие соединения — надо разрешить. Если
пропустили: Системные настройки → Сеть → Файрвол → Параметры.

## Шаг 3: сценарий проверки

Порядок важен: каждый пункт опирается на предыдущий.

1. **Видят ли друг друга.** Запустить оба, открыть «Устройства». В разделе «Найдены в
   сети» должно появиться второе устройство. Не появилось — дело в сети или файрволе,
   дальше идти бессмысленно.
2. **Связывание.** На машине A: «Показать приглашение» → появится QR и строка.
   На машине B: вставить строку в «Подключиться по токену» → устройство в «Доверенных».
   Если есть телефон — попробуйте навести камеру на QR, это проверит читаемость с экрана
   (в приложении сканирования пока нет, но камера телефона покажет строку).
3. **Разовая передача.** На A: «Передача» → выбрать файл → выбрать B → «Отправить».
   На B должна появиться карточка «Принять файлы от…». Принять — файл появится в папке
   загрузок с сохранённой датой изменения.
4. **Отказ.** Повторить и нажать «Отклонить» — у отправителя должна быть внятная
   причина, у получателя ничего не появиться.
5. **Синхронизация папки.** На обеих машинах добавить хранилище (кнопка «Обзор…»),
   поделиться им с другим устройством, нажать «Синхронизировать».
6. **Изменение файла.** Изменить файл на A, подождать пару секунд (авто-синк по
   изменениям) или нажать «Синхронизировать». На B содержимое должно обновиться.
7. **Конфликт.** Изменить **один и тот же** файл на обеих машинах по-разному,
   синхронизировать. Должны остаться обе версии: своя под исходным именем, чужая — с
   пометкой `sync-conflict`. Ничего потеряться не должно.
8. **История версий.** «Хранилища» → «История версий» → выбрать хранилище и файл →
   «Восстановить». Файл должен вернуться к прошлому содержимому.
9. **Большой файл.** Передать что-нибудь на несколько сотен мегабайт: проверяются
   прогресс, отмена и то, что память не улетает.

## Что записывать

По каждому пункту: сработало / не сработало / сработало не так. Для «не так» —
что именно на экране и что в терминале (приложение пишет туда мало, но ошибки видны).

Это первый прогон вне loopback, так что находки вероятны. Все три дефекта среза 31
нашлись именно перебором сценариев, а не тестами.

## Чего эта проверка не покрывает

- Поведение при обрыве сети посреди передачи.
- Разные версии ОС и файловые системы (регистр имён, длинные пути).
- Работу неделями: рост архива версий, утечки.
