# Рефлексия: синк по локальным изменениям файлов

Честный самоанализ. Дата: 2026-08-01.

## Что сделал

`IChangeNotifier` (ядро), расширил `AutoSyncCoordinator` (помнит найденные доверенные
устройства + синкает на сигнал изменения), `FileSystemChangeNotifier` (watcher + дебаунс,
инфраструктура), проброс в голове. 4 юнит-теста координатора (2 новых) + интеграционный
тест наблюдателя. Всего 191 тест, Release чистый.

## Что получилось хорошо

- **Держал фокус — не раздул.** Ровно одна абстракция (`IChangeNotifier`), минимальное
  расширение координатора (запомнить peer'ов + реагировать), тонкий watcher. Никаких
  новых подсистем.
- **Тестируемое отделено от ФС.** Реакция координатора на изменение — чистый юнит с
  фейком; реальный `FileSystemWatcher` — отдельный интеграционный тест. Дедупликация
  переиспользована из авто-синка (изменение во время идущего синка не плодит второй).
- **Слои целы:** ядро зависит от `IChangeNotifier`, конкретный watcher — в инфраструктуре,
  композиция — в голове.

## Что бы пересмотрел / техдолг (явно)

1. **Наблюдаются только хранилища на момент запуска.** Добавил хранилище в UI — watcher
   его не видит до перезапуска. Осознанное сужение; когда появится UI управления
   хранилищами, watcher надо переинициализировать при изменении списка.
2. **Дебаунс фиксированный (2с).** Разумный дефолт, но при массовом копировании файлов
   один сигнал может прийти рано/поздно. Пока не настраиваем.
3. **Синкает со всеми известными при любом изменении.** Не различает, в каком именно
   хранилище изменение — синкает все хранилища со всеми найденными. Для текущей модели
   «делишь всё» это ок; при per-link auto_sync нужно точечнее.
4. **`FileSystemWatcher` известен капризами** (переполнение буфера при массе событий,
   различия по ОС). Дебаунс сглаживает, но при больших деревьях стоит следить за
   `InternalBufferSize`/потерей событий.

## Вывод

Небольшой, но важный срез: «постоянный синк» стал действительно постоянным — реагирует и
на появление устройства, и на изменение файлов, оставаясь в тех же слоях и дедупликации.
Главный осознанный долг — переинициализация watcher при изменении списка хранилищ (всплывёт
вместе с UI управления хранилищами). Дальше по плану: UI связывания хранилищ↔устройств
(№2) или вкладка «Медиа» (№3).
