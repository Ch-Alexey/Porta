# Рефлексия: 32. История версий — ротация и откат

## Что сделал

Закрыт долг из ревизии: архив версий больше не растёт бесконечно и стал доступен
человеку.

- `FileSystemVersionStore.MaxVersionsPerFile` (по умолчанию 10) — лишние старые копии
  удаляются после каждой записи.
- `IVersionArchive` / `FileSystemVersionArchive` — перечислить файлы с версиями,
  перечислить версии, откатиться. Он же выдаёт `IVersionStore` для синхронизации, так
  что голова перестала склеивать пути руками.
- Раздел «История версий» на вкладке «Хранилища»: хранилище → файл → список версий с
  датой и размером → «Восстановить».

Тесты: +16. Итого 339 зелёных, Release 0 предупреждений.

## Главное

**Тест нашёл дефект, который уронил бы синхронизацию.** При написании тестов
view-модели упало `IOException: file already exists`. Причина настоящая, не тестовая:
две версии, сохранённые в одну и ту же миллисекунду, просятся в одно имя, а
`File.Copy(overwrite: false)` на это падает — и падение вылетает наружу через
`SyncApplier`, то есть **роняет весь синк**.

Это не выдумка: файл могут изменить и синхронизировать дважды подряд, а откат вообще
архивирует текущее содержимое непосредственно перед записью — два обращения к архиву
подряд по определению. Починил сдвигом метки на миллисекунду вперёд, пока имя не
освободится: формат имени сохраняется, и порядок по имени остаётся порядком по времени.
Закрепил тестом с **остановленными** часами — худший случай.

Дефекту был месяц: код написан на срезе 11 и всё это время имел зелёные тесты.

**Откат сначала архивирует текущее.** Иначе откат сам стал бы способом потерять данные:
передумал — вернуть нечего. Есть отдельный тест «откат можно откатить».

**Ротация по числу, а не по объёму.** «Последние 10 правок» — гарантия, которую человек
держит в голове; лимит по объёму осмысленнее для больших архивов, но требует обхода
всего дерева при каждой записи. Осознанный размен, записываю как таковой.

## Оговорки и техдолг

- **Ограничения по объёму архива нет.** Десять версий файла на 2 ГБ — это 20 ГБ. При
  ротации только по числу такое возможно, и пользователь об этом нигде не предупреждён.
- **Содержимое версии нельзя посмотреть до отката** и нельзя сравнить две версии —
  выбор идёт вслепую, по дате и размеру.
- **Список версий не обновляется сам** — после синхронизации нужно нажать «Обновить».
- **Откат не спрашивает подтверждения.** Текущее содержимое при этом архивируется, так
  что потерять ничего нельзя, но нажатие необратимо в один клик.
- **Ротация удаляет молча.** Если удалить старую копию не удалось (файл занят), ошибка
  проглатывается, чтобы не ронять синк, — но и не сообщается.
