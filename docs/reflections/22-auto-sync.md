# Рефлексия: авто-синхронизация

Честный самоанализ. Дата: 2026-08-01.

## Что сделал

Перенёс `ISyncController` в ядро (общая абстракция для кнопки и авто-синка), написал
`AutoSyncCoordinator` (discovery → авто-синк доверенных, с дедупликацией), подключил в
голове. 4 юнит-теста координатора + сквозной `AutoSyncE2ETests` (B авто-синкает с A по
реальному mDNS+QUIC). Всего 188 тестов, Release чистый.

## Что получилось хорошо

- **«Ощущение Dropbox» реально работает** — и это доказано E2E-тестом: без кнопки,
  устройство появилось → файлы синхронизировались. Автоматизация поверх уже проверенных
  кубиков (discovery + SyncService) легла тонким слоем.
- **Дедупликация продумана и покрыта:** повторное обнаружение того же устройства во время
  идущего синка не плодит параллельные синки. Тест на это — деликатная часть, сделал её
  детерминированной (блокирующий/синхронный фейки вместо таймингов).
- **Унификация абстракции:** `ISyncController` теперь одна, в ядре; и кнопка, и авто-синк
  зовут её. Меньше дублирования, чем если бы завёл отдельный `ISyncTrigger`.
- **Тихий авто-синк** — ошибки не всплывают модалками; это правильно для фонового процесса.

## Что бы пересмотрел / техдолг (явно)

1. **Синкает все хранилища скопом с любым доверенным устройством.** Модель `storage_devices.
   auto_sync` (связь хранилище↔устройство) есть в БД, но не используется — потому что нет
   **UI для связывания** хранилищ с устройствами. Пока «доверяешь устройству → делишь с ним
   всё». Это огрубление; нужен экран связывания и учёт per-link auto_sync.
2. **Только триггер «устройство появилось».** Нет реакции на **локальные изменения файлов**
   (нужен FileSystemWatcher → синк) и нет периодического синка. Для настоящего постоянного
   синка это ключевое — сейчас, если оба уже онлайн и файл поменялся, авто-синк не сработает
   до переобнаружения.
3. **Нет обратного направления при авто-синке.** B тянет у A; чтобы сошлись, A тоже должен
   тянуть у B. Сейчас каждый тянет при обнаружении другого — но это два независимых pull, а
   не согласованный двусторонний проход. Обычно сойдётся за два срабатывания, но формально
   двусторонней конвергенции за сеанс нет (долг тянется с Этапа 4).
4. **Нет UI-индикатора авто-синка.** Пользователь не видит, что идёт/прошёл фоновый синк.
   Нужен статус/иконка/лог.
5. **Дедуп по устройству, не по (устройство, хранилище).** Пока один синк на устройство
   разом — ок, т.к. синкаем все хранилища в одном вызове; при разбиении на per-storage
   надо уточнить ключ дедупа.

## Вывод по процессу

Авто-синк — логичное завершение UI-ветки синхронизации: продукт теперь «сам» синхронизирует
при появлении доверенного устройства, и это проверено сквозным тестом на реальном стеке.
Честно: до «настоящего постоянного Dropbox» не хватает **реакции на изменения файлов**
(watcher) и **UI связывания хранилищ с устройствами** (чтобы auto_sync был выборочным).
Оба — очевидные следующие срезы. Плюс давний долг двусторонней конвергенции.
