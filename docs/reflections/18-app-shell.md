# Рефлексия: приложение и UI-оболочка

Честный самоанализ. Дата: 2026-08-01.

## Что сделал

`AppEnvironment` (bootstrap: папка данных, личность, БД, репозитории) и первый
**запускаемый** Avalonia-UI: шапка с реальным Device ID, вкладки «Хранилища» (список +
добавление) и «Устройства» на данных из SQLite. Проверено запуском: приложение создаёт
`~/Library/Application Support/Porta` (`device.key` 0600, `porta.db` v2) и стартует без
ошибок.

## Что получилось хорошо

- **Впервые продукт запускается и показывает реальные данные ядра.** Не мок — настоящий
  Device ID из личности и реальные таблицы SQLite. Весь бэкенд, что копили с Этапа 1,
  наконец «ожил» за UI.
- **`AppEnvironment` — чистая единая точка входа.** Ядро не знает про UI; приложение
  инициализирует всё одним вызовом. Легко будет подключить те же репозитории к синку/
  discovery.
- **Проверил запуском, а не «на глаз»:** убедился, что процесс стартует без краша и что
  данные реально созданы (ключ с правами 0600, миграции применились). Это честнее, чем
  «собралось — значит работает».
- **Чисто:** 0 предупреждений сборки (заменил устаревший `Watermark`, убрал
  несуществующие тематические ресурсы).

## Что бы пересмотрел / техдолг (явно)

1. **UI ничего не делает, кроме отображения и добавления хранилища.** Ни выбора папки
   диалогом (путь вводится руками — легко ошибиться), ни связывания, ни запуска синка,
   ни discovery, ни «Медиа». Это только оболочка; ценность появится, когда кнопки
   поедут в ядро.
2. **Нет UI-тестов.** Проверка — ручной запуск. Хотя бы smoke-тест на конструирование
   VM с фейковым окружением стоит добавить (сейчас VM требует настоящий `AppEnvironment`
   с диском — надо ввести интерфейс/абстракцию, чтобы VM тестировались без файловой системы).
3. **VM жёстко завязаны на `AppEnvironment`.** Для тестируемости и design-time лучше
   абстрагировать доступ к данным (интерфейсы репозиториев) и внедрять их. Пока
   прагматично, но это долг перед ростом UI.
4. **Имя устройства = имя машины, без персистентности.** `settings`-таблица есть, но не
   используется; имя нельзя сменить. Подключить `SettingsRepository`.
5. **Мобильные/браузерная головы всё ещё вне solution.** UI писал под десктоп; на
   мобильных те же VM должны работать, но не проверял (нет workloads).
6. **Design-time превью выключено** (VM требует окружение). Мелочь, но разработчику UI
   удобнее с превью — вернуть через design-time абстракцию.

## Вывод по процессу

Психологически важный срез: месяцы бэкенда впервые стали видимым приложением, и это
проверено запуском, а не только сборкой. Но честно: это **оболочка**, а не рабочий
клиент синхронизации — кнопки пока не связаны с транспортом/синком/discovery. Ближайший
по ценности долг — абстрагировать данные для тестируемости VM и начать соединять UI с
уже готовым ядром (связывание, запуск синка).
