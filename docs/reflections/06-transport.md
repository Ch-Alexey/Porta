# Рефлексия: Этап 3 — Transport (срез 1: сертификат)

Честный самоанализ. Дата: 2026-07-30.

## Что сделал

`DeviceIdentity.CreateSelfSignedCertificate` (самоподписанный X.509 из ключа устройства,
CN=DeviceId, расширения BasicConstraints/KeyUsage) и `DeviceCertificate` (`FromCertificate`,
`Matches`) — проверка сертификата по закреплённому Device ID. 5 тестов, все зелёные (80 в ядре).

## Что получилось хорошо

- **Одним срезом закрыл два долга** из прошлых рефлексий: генерацию TLS-сертификата
  (долг Identity) и обязательную проверку ключа сети (долг Pairing).
- **Сертификат самопривязан к Device ID** — публичный ключ сертификата тот же, что у
  устройства, так что доверять «имени» в сертификате не нужно, только хешу ключа. Тест
  `Certificate_is_bound_to_device_id` фиксирует это свойство.
- **Проверил выполнимость окружения до вложения в код** (см. ниже) — тот же приём, что
  выручил с mDNS.

## Ключевая находка: QUIC недоступен в текущем окружении

`QuicListener.IsSupported == False` — на этой macOS нет `libmsquic`, которую требует
`System.Net.Quic`. ADR-0006 помечал это риском; риск материализовался.

**Вывод (осознанный):** не писать сейчас реальный QUIC-listener/connector, который
негде прогнать интеграционно. Это был бы ровно тот непокрытый сетевой код, против
которого я возражал в рефлексии по discovery. Решение о дальнейшем пути транспорта
вынесено пользователю (установить libmsquic / TLS-over-TCP как разрешённый ADR-0006
fallback / только чистая логика протокола).

## Техдолг/на заметку

1. **PFX round-trip.** На части платформ `X509Certificate2` из `CreateSelfSigned` нужно
   экспортировать/переимпортировать (PFX), чтобы приватный ключ работал в TLS-стеке.
   Проверить при реальном хендшейке.
2. **Срок и ротация сертификата.** Пока просто задаём период. Нужна политика
   продления/ротации и что делать с истёкшим у долгоживущего устройства.
3. **Абстракция транспорта ещё не введена** — сертификат готов, но `ITransport`
   появится вместе с выбранной реализацией (следующий срез).

## Обновление: срез 2 — QUIC-транспорт готов

Пользователь поставил libmsquic; выяснилось, что .NET не находит её в пути Homebrew
(`/opt/homebrew/lib`) — заработало через `DYLD_LIBRARY_PATH=/opt/homebrew/opt/libmsquic/lib`.
Реализованы `ITransport`/`IPeerConnection`/`ITransportListener` (ядро) и `QuicTransport`
(инфраструктура). Интеграционный тест: два узла на loopback, взаимный pinning, обмен
данными по потоку, и отдельный тест на отклонение неверного pin. Все зелёные.

### Что получилось хорошо (срез 2)

- **Взаимная аутентификация по Device ID работает по-настоящему,** а не в теории:
  клиент пинит сервер, сервер вычисляет Device ID клиента из его сертификата. Тест на
  неверный pin подтверждает, что чужого не пустит — это и есть закрытие долга Pairing
  «сеть обязана доказать владение ключом».
- **Абстракция в ядре чиста от QUIC** — `System.Net.Quic` только в инфраструктуре;
  ITransport можно реализовать и через TLS/TCP (fallback из ADR-0006), не трогая ядро.
- **Честный гейт `IsSupported`** — без libmsquic тесты тихо пропускаются, обычный
  прогон не краснеет; полный прогон — с DYLD-путём.

### Техдолг/риски (срез 2) — явно

1. **QUIC-тесты пропускаются без libmsquic** — это скрытый риск: в CI без библиотеки
   они не выполнятся и регрессию не поймают. Нужно поставить libmsquic в CI или
   гонять транспортные тесты в выделенном окружении. Пока помечены `Integration`.
2. **Зависимость от libmsquic и её пути** — на macOS требуется `DYLD_LIBRARY_PATH`.
   Для реального приложения нужно решить поставку библиотеки (bundle/установка) —
   иначе у пользователя QUIC не заведётся. На мобилках доступность msquic ещё предстоит
   проверить (риск из ADR-0006 не снят, только для десктопа).
3. **Сервер принимает любой сертификат** и лишь отдаёт `RemoteDeviceId` — сверку с
   доверенными устройствами (репозиторий) слой выше пока не делает. До реального
   использования соединение от недоверенного устройства нужно закрывать.
4. **Один поток, без протокола.** Пока просто «открыть поток, передать байты». Нет
   ни фрейминга сообщений, ни мультиплексирования логических каналов, ни backpressure.
5. **Провал pinning — `ThrowsAnyAsync`.** Тип исключения не зафиксирован (может быть
   `AuthenticationException`/`QuicException`). Стоит уточнить и, возможно, обернуть в
   доменное исключение транспорта, чтобы слой выше отличал «не тот ключ» от «сеть упала».
6. **PFX round-trip** сделан на всякий случай; не проверял, обязателен ли он на всех
   платформах. Оставил как защиту, но это лишняя аллокация/копия ключа — перепроверить.

## Вывод по процессу

Срез сертификата дал криптофундамент и заранее вскрыл блокер (нет msquic), не потратив
время на непроверяемый код; после установки libmsquic QUIC-канал собрался и прошёл
интеграционно с первого содержательного захода. Главный непокрытый в CI риск — сама
доступность libmsquic; это теперь ключевой вопрос поставки транспорта, а не логики.
