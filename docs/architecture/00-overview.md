# Обзор архитектуры Porta

## Принцип

Porta — децентрализованное (P2P) приложение. Каждое устройство равноправно: оно
одновременно и клиент, и «сервер» своего локального хранилища. Центрального облака
нет — устройства находят друг друга в сети и обмениваются данными напрямую.

## Компоненты ядра

### Identity — личность устройства и доверие
- Генерация пары ключей при первом запуске (Ed25519 для подписи / X25519 для обмена).
- **Device ID** = отпечаток публичного ключа.
- **Pairing:** устройство показывает QR-код / ссылку с Device ID + сетевым адресом
  + одноразовым кодом. Второе устройство сканирует → взаимное доверие.
- Доверенные устройства и их ключи хранятся локально; TLS-соединения проверяются
  по этим ключам (pinning).

### Discovery — обнаружение в локальной сети
- **mDNS/DNS-SD** (объявление сервиса `_porta._tcp`) или UDP-broadcast как fallback.
- Результат — список видимых устройств с их адресами; доверие проверяется отдельно
  (Identity).

### Transport — передача данных
- Защищённый канал: **QUIC** (`System.Net.Quic`) со встроенным TLS 1.3 —
  мультиплексирование потоков и устойчивость к смене сети. См. [ADR-0006](../adr/0006-transport-quic.md).
- Доверие — проверка сертификата по закреплённому ключу устройства (pinning).
- Транспорт скрыт за абстракцией: при проблемах с QUIC на какой-то платформе можно
  подставить fallback (TLS/TCP), не трогая протокол.
- По каналу ходят сообщения протокола: обмен индексами, запрос блоков, передача
  блоков, служебные сообщения.

### Indexer — индексация файлов
- Сканирует папки хранилища, считает метаданные (путь, размер, mtime) и хеши.
- **Content-defined chunking**: файл режется на блоки по содержимому (rolling hash),
  каждый блок хешируется. Это позволяет при изменении файла передавать только
  затронутые блоки.
- Строит дерево хешей (Merkle) для быстрого сравнения состояний между устройствами.

### Sync — синхронизация
- Сравнивает индексы двух устройств, вычисляет разницу (какие блоки недостающие).
- Запрашивает и применяет только изменения.
- **История изменений:** журнал операций; предыдущие версии файлов сохраняются.
- **Конфликты:** version vectors определяют, какая версия новее или что это
  конфликт (тогда обе версии сохраняются, пользователь решает).

### Storage — локальное хранилище метаданных
- **SQLite** (`Microsoft.Data.Sqlite`): устройства, хранилища, индекс файлов и
  блоков, журнал версий, настройки.
- Сами файлы лежат в файловой системе; в БД — метаданные и история.

### MediaScanner — вкладка «Медиа»
- Отдельный сканер устройства по типам файлов (фото, видео, при желании — другие).
- Извлекает EXIF (дата съёмки, GPS), генерирует превью/thumbnails.
- На мобилках работает через платформенный доступ к галерее с запросом разрешений.
- Индекс медиа — тоже в SQLite, для быстрого поиска и фильтрации.

## Потоки данных (упрощённо)

**Связывание устройств:**
```
Устройство A: показать QR (DeviceID_A + адрес + одноразовый код)
Устройство B: отсканировать → подключиться → взаимно проверить ключи → добавить в доверенные
```

**Синхронизация хранилища:**
```
A и B соединены (TLS, доверие проверено)
  → обмен индексами (метаданные + хеши блоков)
  → вычисление разницы
  → запрос недостающих блоков
  → передача блоков → сборка файлов → запись в журнал версий
```

## Решённые вопросы

- **Формат протокола:** MessagePack. См. [ADR-0004](../adr/0004-protocol-format.md).
- **Модель хранилищ:** несколько именованных папок, как в Syncthing. См. [ADR-0005](../adr/0005-storage-model.md).
- **Транспорт:** QUIC + TLS 1.3 (шифрование обязательно). См. [ADR-0006](../adr/0006-transport-quic.md).
- **Удаления:** не распространяются (задел на «подсветку отсутствующих» позже). См. [features/00-functionality.md](../features/00-functionality.md#6).

## Открытые вопросы (решаем по мере продвижения)

- Стратегия версионирования: сколько версий хранить, где, как чистить.
- Библиотека mDNS для discovery (кандидаты: Makaretu.Dns, Zeroconf).
- Режим медиа-вкладки: инструмент поиска-и-отправки vs умная галерея с постоянным индексом.
- Доступность msquic на iOS/Android (проверить на этапе транспорта).
