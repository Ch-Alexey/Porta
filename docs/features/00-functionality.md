# Функциональность Porta — общая картина (согласовано, черновик развивается)

> Описание **что делает продукт с точки зрения пользователя**, без деталей
> реализации. Технические решения — в [`../adr/`](../adr/) и
> [`../architecture/`](../architecture/).

## 1. Суть в одном абзаце

Porta ставится на любое устройство (ПК, ноутбук, телефон) и превращает его в узел
личной сети обмена файлами. Устройства пользователя связываются напрямую (P2P), без
облака-посредника, и обмениваются данными двумя способами: **разовая передача**
(просто отправить файлы на другое своё устройство) и **синхронизируемые папки**
(папки, которые постоянно поддерживаются в актуальном состоянии между устройствами).
Плюс — отдельный инструмент поиска фото и видео по всему устройству. Вся передача
зашифрована. На старте всё работает в пределах локальной сети.

## 2. Ключевые понятия

- **Устройство** — установленный экземпляр Porta. У каждого свой постоянный
  идентификатор (Device ID) на основе криптоключа. Все устройства равноправны.
  Новое устройство = новая личность (ключи не переносятся).
- **Доверие** — два устройства один раз «знакомятся» через QR-код или ссылку с
  одноразовым кодом. После этого доверяют друг другу. Без паролей и аккаунтов.
- **Разовая передача (Drop)** — отправка выбранных файлов на другое устройство «как
  есть», без постоянной связи. Аналог «закинуть в Загрузки». Метаданные файлов
  сохраняются.
- **Синхронизируемое хранилище (папка)** — папка, которую пользователь держит в
  синхроне между устройствами. У хранилища есть ID и имя; одно хранилище может быть
  подключено на нескольких устройствах. Структура вложенных папок сохраняется.
  Хранилищ может быть много, каждое независимо.
- **Авто-синхро пара** — пара устройств, между которыми настроена автоматическая
  синхронизация. Устройство помнит такие пары и при запуске проверяет их доступность.
- **Версия файла** — сохранённое прошлое состояние файла. История даёт откат и
  помогает передавать только изменения.

## 3. Безопасность (обязательные требования)

- **Шифрование при передаче** — весь трафик между устройствами зашифрован
  (транспорт QUIC со встроенным TLS 1.3, см. [ADR-0006](../adr/0006-transport-quic.md)).
- **Доверие по ключам** — соединение принимается только от устройств, чьи ключи мы
  подтвердили при связывании (pinning). Чужие подключиться не могут.
- **Новое устройство = новая личность** — ключи не экспортируются и не переносятся;
  это осознанно упрощает модель безопасности.
- **Никакого авто-удаления** данных (особенно медиа) при автоматической синхронизации.

## 4. Разделы приложения (вкладки)

### 4.1 Устройства
- Список моих устройств: имя, тип, онлайн/оффлайн, последняя активность.
- **«Добавить устройство»** → показать QR-код и ссылку для связывания.
- **«Подключиться к устройству»** → сканировать QR / вставить ссылку.
- По каждому устройству: общие хранилища, статус синхронизации, включена ли
  авто-синхро.
- Отзыв доверия (удалить устройство).

### 4.2 Отправить (разовая передача)
- Выбрать файлы/папки → выбрать устройство-получатель → отправить.
- **Получатель подтверждает приём** («Принять файлы от устройства A?»); только после
  согласия файлы принимаются.
- После подтверждения файлы приходят в заданную папку (условные «Загрузки»), с
  сохранением метаданных.
- Не создаёт постоянной связи и не отслеживает изменения — это именно «передать и всё».

### 4.3 Хранилища (синхронизация)
- Список хранилищ: имя, путь на этом устройстве, размер, статус (в синхроне /
  синхронизируется / приостановлено).
- **Создать хранилище** → выбрать папку, задать имя, выбрать устройства.
- **Присоединиться к хранилищу** → получить ID существующего хранилища с другого
  устройства, указать локальную папку.
- Настройки хранилища:
  - **режим синхронизации:** переключатель авто / ручной (по умолчанию — авто);
  - режим обмена: двусторонний / только приём / только отдача;
  - политика версий (сколько хранить, как долго);
  - игнор-паттерны (`*.tmp`, `node_modules`, …);
  - пауза/возобновление.
- **Структура вложенных папок сохраняется** при синхронизации.
- **Удаления не распространяются** (см. раздел 6).

### 4.4 Синхронизация / Активность
- Общий статус: что передаётся, сколько осталось, скорость.
- Лента событий: файл добавлен/изменён, с какого устройства, когда.
- **История версий** файла: список прошлых версий; действия — просмотреть,
  восстановить, сохранить как копию.
- **Конфликты**: если файл менялся на двух устройствах — обе версии сохраняются,
  пользователь выбирает.

### 4.5 Медиа (поиск фото/видео)
- Сканирует **всё устройство** (не только хранилища), находит фото и видео (позже —
  возможно другие типы).
- Просмотр сеткой превью; фильтры по дате (EXIF), типу, папке; в перспективе —
  место съёмки (GPS), дубликаты.
- Действие: выбрать найденное и **отправить** (разово) или **добавить в хранилище**.
- На мобильных — доступ к системной галерее с запросом разрешений.
- **Режим v1: инструмент поиска-и-отправки** (сканирует по запросу, постоянного
  каталога не ведёт). Модель данных закладываем с прицелом дорасти до «умной
  галереи» (постоянный индекс, превью, места) без переделки.

### 4.6 Настройки
- Имя этого устройства, Device ID (показать/скопировать).
- Сеть (порт, разрешить discovery в LAN).
- **Автозапуск** приложения (задел): при старте проверять доступность авто-синхро
  устройств и синхронизироваться, если в сети.
- Куда складывать разовые передачи (папка «Загрузки»).
- Тема оформления, работа в фоне.

## 5. Основные пользовательские сценарии

**Первый запуск.** Генерируется личность устройства (ключи, Device ID), предлагается
задать имя. Списки устройств и хранилищ пусты.

**Связывание устройств.** A → «Добавить устройство» → QR-код. B → «Подключиться» →
сканирует QR / вставляет ссылку. Устройства проверяют ключи и доверяют друг другу.

**Разовая передача.** Выбираю на A несколько фото → «Отправить» → устройство B. На B
они появляются в «Загрузках» с сохранёнными метаданными. Связь не остаётся.

**Синхронизируемое хранилище.** На A создаю хранилище «Документы» из папки, выбираю B
и режим (авто/ручной). На B принимаю, указываю локальную папку. Файлы едут с
сохранением структуры; передаются **только изменившиеся части**. При авто-режиме
дальнейшие изменения подхватываются сами.

**Авто-синхро при запуске (задел на будущее).** Устройство знает свои авто-синхро
пары. При запуске проверяет, кто из них в сети, и синхронизирует общие хранилища без
участия пользователя. Медиа при этом никогда не удаляется автоматически.

**Откат версии.** История файла → выбрать прошлую версию → восстановить.

## 6. Обработка удалений (текущее решение)

- **Удаления НЕ распространяются между устройствами.** Если файл удалён на A, на B он
  остаётся. Это защищает от случайной потери данных.
- **Задел на будущее:** возможность подсветить файлы, которые есть на одном
  устройстве, но отсутствуют на другом (чтобы пользователь сам решил). **Сейчас не
  разрабатываем**, но модель данных должна это позволить позже.

## 7. Границы первой версии

**Входит:** LAN; связывание по QR + доверие по ключам; разовая передача;
синхронизируемые хранилища (двусторонние, авто/ручной переключатель); передача только
изменений; история версий; конфликты; сохранение метаданных и структуры папок;
шифрование трафика; вкладка поиска фото/видео с базовыми фильтрами.

**Пока НЕ входит:** распространение удалений; работа через интернет/другие сети;
шаринг с чужими людьми; экспорт/перенос личности; продвинутый медиа-поиск (GPS,
распознавание, дубликаты); мобильный и браузерный UI (ядро к ним готово, включаем
поэтапно).
