# Фича: разрешение конфликтов (срез B)

**Статус:** готово (срез B) · **Слой:** `Porta.Core/Sync`

Готово: `SyncAction`, `ConflictResolver.Decide`/`ConflictName`. 8 тестов. Применение к
файлам — [срез C](16-conflict-apply.md).

Опирается на [version vectors](13-version-vectors.md) и [версионированный индекс](14-versioned-index.md).
Определяет, что делать с файлом при синхронизации, и как назвать конфликтную копию.

## Решение (`ConflictResolver.Decide`)

По локальной версионированной записи (или её отсутствию) и удалённой:

| Ситуация | Действие (`SyncAction`) |
|---|---|
| Локального файла нет | `Accept` (взять удалённый) |
| Удалённая версия доминирует | `Accept` (удалённый новее) |
| Локальная версия доминирует | `Skip` (мы новее) |
| Версии равны, контент совпадает | `Skip` |
| Версии равны, контент разный | `Conflict` (несогласованность) |
| Параллельные правки | `Conflict` |

## Конфликтная копия (`ConflictResolver.ConflictName`)

При конфликте локальный файл сохраняется как есть, а удалённая версия пишется под именем
(стиль Syncthing):

```
<имя>.sync-conflict-<ГГГГММДД-ЧЧММСС>-<короткий DeviceId>.<ext>
```

Пользователь потом выбирает, что оставить (см. [функциональность 4.4](00-functionality.md)).

## Границы среза

- Чистая логика решения и имя копии — **с тестами**.
- Применение в реальном синке (двусторонний обмен версионированными индексами,
  запись конфликтной копии, персистентность версий) — срез C.

## Тесты

- Нет локального → Accept; удалённый доминирует → Accept; локальный доминирует → Skip;
  равные версии + тот же контент → Skip; равные версии + разный контент → Conflict;
  параллельные правки → Conflict.
- `ConflictName`: маркер и метка времени вставлены перед расширением, каталог сохранён;
  файл без расширения.
