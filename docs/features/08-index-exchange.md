# Фича: обмен индексами и вычисление дельты

**Статус:** первый срез готов (сериализация индекса + дельта) · **Слой:** `Porta.Core/Sync`, `Porta.Core/Protocol`

Готово: разметка `FileIndexEntry`/`ChunkInfo` для MessagePack, `FolderIndexMessage`,
`IndexComparer`/`IndexDiff`/`NeededBlock`. 6 юнит-тестов (сравнение + round-trip) +
интеграционный обмен индексом поверх QUIC с вычислением дельты.

Опирается на индексатор ([03-indexer](03-indexer.md)), протокол ([07-protocol](07-protocol.md)),
модель хранилищ ([02-data-model](02-data-model.md)).

## Зачем

Чтобы передавать **только изменившееся**, две стороны сравнивают индексы хранилища и
вычисляют, каких блоков не хватает принимающей стороне. Это ядро дельта-синхронизации
(идея Block Exchange из Syncthing, [ADR-0003](../adr/0003-syncthing-reference.md)).

## Сообщение

`FolderIndexMessage(StorageId, Entries)` — индекс хранилища на проводе. Несёт список
`FileIndexEntry` (путь, размер, mtime, контент-хеш, блоки). Доменные типы `FileIndexEntry`
и `ChunkInfo` размечены атрибутами MessagePack — формат протокола прямо на C#-типах
([ADR-0004](../adr/0004-protocol-format.md)).

## Вычисление дельты (`IndexComparer`)

Вход: локальный индекс и удалённый индекс (списки `FileIndexEntry`).
Выход: `IndexDiff`:
- **`FilesToUpdate`** — файлы, которые есть у удалённого и которых у нас нет или у
  которых **отличается контент-хеш** (новые/изменённые).
- **`MissingBlocks`** — различные блоки (по хешу), нужные для этих файлов, которых
  **нет ни в одном** локальном файле. Дедупликация: блок с известным хешем не
  запрашиваем, даже если он лежит в другом файле — это и даёт экономию rsync-типа.

**Удаления не распространяются** ([features/00](00-functionality.md#6)): файлы, которые
есть локально, но отсутствуют у удалённого, — **игнорируются**, не удаляются.

## Границы среза

- Сериализация индекса + вычисление дельты — **с тестами**.
- Собственно запрос и передача недостающих блоков, сборка файла, запись версии —
  следующий срез.
- Запрос индекса по инициативе (request/response поверх нескольких сообщений),
  инкрементальные обновления индекса — позже.

## Тесты

- `IndexComparer`: новый файл у удалённого → в `FilesToUpdate`, его блоки в `MissingBlocks`;
  идентичные индексы → пустая дельта; изменённый файл (1 блок из N) → нужен только
  изменившийся блок (остальные дедуплицированы); блок, уже присутствующий в другом
  локальном файле, не запрашивается; локальный-только файл игнорируется (нет удаления).
- `FolderIndexMessage` round-trip через `MessageChannel` (включая реальный вывод
  `FolderScanner`).
- Интеграционно поверх QUIC: сторона A шлёт индекс, сторона B читает и вычисляет дельту.
