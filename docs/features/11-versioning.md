# Фича: версионирование (история версий файлов)

**Статус:** первый срез готов (архивирование при перезаписи) · **Слой:** `Porta.Core/Sync`

Готово: `IVersionStore` + `FileSystemVersionStore` (`Archive`/`ListVersions`, `TimeProvider`),
интеграция в `FileAssembler.Write` и `SyncProtocol.PullAsync`. 7 тестов (хранилище версий,
сборка с архивом, синк с сохранением прежней версии).

Закрывает продуктовое обещание из [00-functionality](00-functionality.md): «история
изменений файлов», «не терять данные». До этого `FileAssembler` перезаписывал файл
молча.

## Идея

Когда синхронизация собирается **перезаписать существующий файл**, его текущее
содержимое сначала архивируется в хранилище версий, откуда версию можно восстановить.

## Компоненты

### IVersionStore
`Archive(filePath, relativePath)` — сохранить текущий файл как версию перед перезаписью.

### FileSystemVersionStore
Кладёт копию в `<versionsRoot>/<относительный путь>` с меткой времени в имени:
`a.txt` → `a~ГГГГММДД-ЧЧММССфф.txt`. Структура папок хранилища зеркалится. Время — через
`TimeProvider` (тестируемо). `ListVersions(relativePath)` — версии файла (для UI/восстановления).

> **Важно:** `versionsRoot` должен быть **вне** синхронизируемой папки, иначе сканер
> подхватит версии и начнёт их синхронизировать. Пока обеспечивается вызывающим; когда
> появятся игнор-паттерны, можно будет держать `.porta/versions` внутри папки.

## Интеграция

- `FileAssembler.Write(..., IVersionStore? versions)` — перед заменой существующего файла
  вызывает `Archive`. Порядок безопасен: архивируем **до** атомарного перемещения нового
  содержимого; при ошибке архива новый файл ещё не на месте, старый цел.
- `SyncProtocol.PullAsync(..., IVersionStore? versions)` — пробрасывает хранилище версий
  в сборку.

## Границы среза

- Архивирование предыдущей версии при перезаписи + перечисление версий — **с тестами**.
- Политика хранения (сколько версий, срок, размер), восстановление через UI, версии при
  удалении — позже.
- Version vectors и разрешение конфликтов — отдельный срез (это про «какая версия
  новее/конфликт», здесь — просто «не потерять старое»).

## Тесты

- `FileSystemVersionStore`: архивирует файл (версия содержит старое содержимое); несколько
  архивов → несколько версий; несуществующий источник → no-op.
- `FileAssembler`: перезапись существующего файла кладёт старое содержимое в версии; новый
  файл (без существующего) версий не создаёт.
- `SyncProtocol`: pull, перезаписывающий изменившийся файл, сохраняет прежнюю версию у
  принимающего.
