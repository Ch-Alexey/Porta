# Фича: Indexer — индексация файлов и chunking

**Статус:** первый срез готов (49 тестов в ядре, зелёные) · **Слой:** `Porta.Core/Indexing`

Реализовано: `ChunkerOptions`, `ChunkInfo`, `FileIndexEntry`, детерминированная
`GearTable` (SplitMix64), `Chunker.Split` (gear-hash CDC с нормализацией), `FolderScanner`.
Свойство CDC (устойчивость к вставке байта) проверено тестом.

## Зачем

Чтобы передавать **только изменившиеся части** файлов, а не файлы целиком, нужно резать
файлы на блоки по содержимому и сравнивать блоки по хешам. Этот срез даёт фундамент:

- **Content-defined chunking (CDC)** — разбивка файла на блоки так, чтобы вставка/удаление
  байтов в начале не сдвигала границы всех последующих блоков.
- **Скан папки** — обход хранилища, метаданные файлов (путь, размер, mtime), список блоков
  и контент-хеш файла.

Индекс потом используется синхронизацией: сравнили списки блоков двух устройств → запросили
недостающие. Это идея Block Exchange из Syncthing ([ADR-0003](../adr/0003-syncthing-reference.md)).

## Алгоритм chunking (gear-hash CDC, вариант FastCDC-lite)

**Скользящий хеш.** Идём по байтам, поддерживаем 64-битный «gear»-отпечаток:
`fp = (fp << 1) + Gear[b]`, где `Gear` — фиксированная таблица из 256 псевдослучайных
64-битных чисел. За счёт сдвига влево старшие биты отражают последние ~десятки байт —
это и есть скользящее окно по содержимому.

**Граница блока** объявляется, когда старшие биты отпечатка обнулены: `(fp & mask) == 0`.
Вероятность ~`2^-k` на байт, где `k` — число единиц в маске, что даёт средний размер
блока ~`2^k`.

**Нормализация (две маски).** Чтобы размеры блоков были ближе к среднему, до достижения
среднего размера используем «строгую» маску `MaskS` (больше бит → резать труднее), после —
«мягкую» `MaskL` (меньше бит → резать легче). Это ключевая идея FastCDC.

**Границы по размеру.** Не режем короче `MinSize` и принудительно режем на `MaxSize`.

**Параметры по умолчанию:** Min = 2 KiB, Avg = 8 KiB, Max = 64 KiB; `MaskS` = старшие 15 бит,
`MaskL` = старшие 11 бит.

### Почему это «content-defined»

Границы зависят только от содержимого окна, а не от абсолютного смещения. Вставили байт
в начало файла — сдвинется только первый затронутый блок, дальше отпечаток «пересинхронизируется»
и последующие блоки (их хеши) останутся прежними. Именно это позволяет передавать дельты.

### Детерминизм между устройствами (критично)

Все устройства обязаны резать одинаково, иначе блоки не совпадут. Поэтому:

- Таблица `Gear` **фиксирована** и генерируется детерминированным `SplitMix64` (свой PRNG,
  стабильный между платформами и версиями .NET — в отличие от `System.Random`).
- Параметры chunking фиксированы (см. выше). При будущей смене — это изменение формата,
  потребует версионирования индекса.

## Модель

- `ChunkInfo(Offset, Length, Hash)` — блок: смещение в файле, длина, SHA-256 содержимого.
- `FileIndexEntry(RelativePath, Size, ModifiedAt, ContentHash, Chunks)` — запись о файле.
  - `RelativePath` — относительный путь с разделителем `/` (нормализуем, чтобы Windows и
    Linux совпадали).
  - `ContentHash` — SHA-256 всего содержимого файла (быстрая проверка «файл не менялся»).
- `ChunkerOptions` — параметры (Min/Avg/Max, маски), `Default`.
- `Chunker.Split(stream, options)` — режет поток на блоки.
- `FolderScanner.Scan(rootPath)` — рекурсивный обход папки → отсортированный список
  `FileIndexEntry`.

## Границы среза

- Только вычисление индекса **в памяти**. Персистентность индекса в SQLite (таблицы
  файлов/блоков, миграция 002) и сравнение индексов — следующие срезы.
- Игнор-паттерны, символические ссылки, скрытые файлы — пока не фильтруем (обход по
  умолчанию). Заложить фильтр позже.
- Потоковая обработка: читаем файл один раз, блок буферизуем до `MaxSize` (64 KiB).

## Тесты

- Пустой поток → 0 блоков; поток меньше `MinSize` → один блок на всё.
- Детерминизм: один вход → одинаковые границы и хеши при повторе.
- **Свойство CDC:** вставка одного байта в начало большого буфера меняет лишь малую часть
  блоков — большинство хешей блоков совпадают с исходными (иначе смысл CDC теряется).
- Инварианты: блоки покрывают весь файл без дыр/нахлёстов; длины в `[Min, Max]` кроме
  последнего; сумма длин = размер.
- `FolderScanner`: относительные пути с `/`, размеры, покрытие блоками, стабильный
  `ContentHash`, сортировка.
