# Фича: Discovery — обнаружение устройств в LAN (mDNS)

**Статус:** готово (чистое ядро + `PeerResolver` — юнит-тесты; реальный mDNS —
интеграционный тест, два узла находят друг друга) · **Слой:** `Porta.Core/Discovery`
(абстракция + чистое), `Porta.Infrastructure` (реализация на Makaretu.Dns)

Логика склейки записей вынесена в `PeerResolver` (тестируемо). Интеграционный тест
(`Porta.Infrastructure.Tests`) вскрыл и закрыл два бага: двойной `.local` в имени
сервиса и отсутствие проактивного `Announce`.

Транспорт/доверие — [ADR-0006](../adr/0006-transport-quic.md); связывание — [04-pairing](04-pairing.md).

## Зачем

Устройства должны находить друг друга в локальной сети без ручного ввода адресов.
Стандарт для этого — **mDNS/DNS-SD** (как Bonjour/AirDrop): устройство объявляет сервис,
остальные его видят.

Discovery только **находит** кандидатов; доверие проверяется отдельно (по Device ID /
ключам из связывания). Незнакомое устройство в списке ≠ доверенное.

## Разделение слоёв

- **`Porta.Core/Discovery`** — модели и абстракция `IDeviceDiscovery` + **чистые
  хелперы** (TXT-записи, имя инстанса). Без сетевых зависимостей → тестируется.
- **`Porta.Infrastructure`** — `MdnsDeviceDiscovery` на `Makaretu.Dns.Multicast`.
  Изолирует зависимость и её транзитивный хвост от ядра. Сетевой код проверяется
  вручную/интеграционно.

Это соответствует «платформенным адаптерам» из [обзора](../architecture/00-overview.md):
ядро остаётся чистым, конкретика — снаружи.

## Протокол объявления (DNS-SD)

- **Тип сервиса:** `_porta._tcp` (домен `local`).
- **Имя инстанса:** Device ID — гарантирует уникальность в сети.
- **Порт:** берётся из SRV-записи (порт QUIC-транспорта).
- **TXT-записи:** `id=<DeviceId>`, `name=<отображаемое имя>`, `v=<версия discovery>`.
  Адреса (A/AAAA) и порт (SRV) публикует сам mDNS-стек.

## Модели и абстракция (в ядре)

- `PortaAdvertisement(DeviceId, Name, Port)` — что объявляет это устройство.
- `DiscoveredPeer(DeviceId, Name, Endpoints, DiscoveredAt)` — найденный кандидат.
- `DiscoveryTxt` — чистый кодек TXT: `Build(advertisement)` → строки; `TryParse(txt)` →
  `(DeviceId, name, version)`. Валидация id и версии.
- `IDeviceDiscovery` — `Advertise(self)`, `StartBrowsing()`, события `PeerDiscovered` /
  `PeerLost`, `IDisposable`.

## Реализация (в инфраструктуре)

`MdnsDeviceDiscovery` на `Makaretu.Dns` (2.0.1) + `Makaretu.Dns.Multicast` (0.27.0):
объявляет `ServiceProfile`, слушает `ServiceInstanceDiscovered`, резолвит SRV/TXT/A →
собирает `DiscoveredPeer`, фильтрует собственный Device ID.

## Границы среза

- Чистое ядро (модели, TXT-кодек, имя инстанса) + абстракция — **с тестами**.
- mDNS-реализация — компилируется и интегрирована; автоматических тестов нет
  (multicast в CI нестабилен), проверка — ручная/интеграционная.
- Сопоставление найденных peer'ов с доверенными и запуск транспорта — Этап 3.
- Мобильные особенности (разрешения/entitlements на multicast) — при подключении
  мобильных голов.

## Тесты (чистое ядро)

- `DiscoveryTxt.Build` даёт ожидаемые `id`/`name`/`v`.
- `TryParse` round-trip id+name+version; имя с пробелами/юникодом/символом `=`.
- Отказ при отсутствии/битом `id`, при отсутствии/неподдерживаемой версии.
- Имя инстанса = Device ID.
