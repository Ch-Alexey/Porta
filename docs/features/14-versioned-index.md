# Фича: версионированный индекс (срез A конфликтов)

**Статус:** готово (срез A) · **Слой:** `Porta.Core/Sync`

Готово: `VersionedFileEntry`, `IndexVersioning.Apply` (инкремент счётчика при изменении).
4 теста.

Первый срез большого блока «двусторонний синк + конфликты». Привязывает
[version vectors](13-version-vectors.md) к файлам и обновляет их при изменении.

## Идея

Чтобы определять конфликты, у каждого файла должна быть версия (version vector), которая
**инкрементится счётчиком этого устройства при каждом локальном изменении**. Сравнивая
версии двух сторон, узнаём: их новее / наше новее / конфликт.

## Компоненты

- `VersionedFileEntry(Entry, Version)` — обёртка: контент-запись файла ([FileIndexEntry](03-indexer.md))
  + её `VersionVector`. Отдельный тип, чтобы не менять `FileIndexEntry` и его формат.
  Сериализуется MessagePack.
- `IndexVersioning.Apply(previous, current, localDeviceId)` — по прежнему
  версионированному индексу и свежему скану выдаёт версионированный индекс:
  - файл не менялся (тот же контент-хеш) → версия сохраняется;
  - файл изменился → `version.Increment(local)`;
  - новый файл → `Empty.Increment(local)` (счётчик этого устройства = 1).
  Чужие счётчики в векторе сохраняются.

## Границы среза

- Привязка версий и их обновление при локальном изменении — **с тестами** (чистая логика).
- Обнаружение конфликтов в синке и «обе версии при конфликте» — срез B.
- Персистентность версионированного индекса между запусками и двусторонний обмен — срез C.
- Учёт удалений в версиях — позже.

## Тесты

- Новый файл → `Version.Get(local) == 1`.
- Неизменившийся файл → версия та же, что была.
- Изменившийся файл → счётчик этого устройства +1.
- Чужой счётчик в прежней версии сохраняется при локальном инкременте.
