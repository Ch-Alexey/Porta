# Фича: version vectors (основа конфликтов)

**Статус:** модель готова · **Слой:** `Porta.Core/Sync`

Готово: `VersionVector` (`Empty`/`Get`/`Increment`/`Merge`/`Compare`), `VectorOrdering`,
MessagePack-сериализация. 7 тестов. Привязка к файлам и использование в синке — следующий срез.

Фундамент для разрешения конфликтов ([00-functionality](00-functionality.md#4.4)):
понять, какая версия файла новее, а какая — конфликт (параллельные правки). Идея из
Syncthing ([ADR-0003](../adr/0003-syncthing-reference.md)), а не «последний по времени
победил».

## Что это

**Version vector** — отображение `Device ID → счётчик`. При каждом локальном изменении
файла устройство увеличивает свой счётчик. Сравнивая два вектора, можно определить
отношение версий **без доверия к часам**.

## Отношения (`VectorOrdering`)

Сравниваем поэлементно (отсутствующий счётчик = 0):

| Ситуация | Отношение |
|---|---|
| Все счётчики равны | `Identical` |
| Наш ≥ во всём и строго больше хотя бы в одном | `Dominates` (наш новее) |
| Наш ≤ во всём и строго меньше хотя бы в одном | `DominatedBy` (их новее) |
| Где-то больше, где-то меньше | `Conflict` (параллельные правки) |

## API

- `VersionVector` (immutable): `Empty`, `Get(deviceId)`, `Increment(deviceId)`,
  `Merge(other)` (поэлементный максимум), `Compare(other) → VectorOrdering`.
- Сериализуется MessagePack (для протокола/хранения индекса позже).

## Границы среза

- Только модель вектора и сравнение — **с тестами**.
- Привязка вектора к записи файла (`FileIndexEntry`), инкремент при изменении в
  индексаторе, использование в синке (конфликт → сохранить обе версии) — следующие срезы.
- Сжатие/очистка векторов (удалённые устройства) — позже.

## Тесты

- `Empty.Compare(Empty)` = Identical; `Increment` увеличивает счётчик.
- Доминирование в одну и другую сторону; равенство.
- Конфликт (где-то больше, где-то меньше).
- `Merge` = поэлементный максимум и доминирует над обоими исходными.
- MessagePack round-trip.
