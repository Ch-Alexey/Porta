# 25. Медиа: сканирование и поиск (срез 1)

## Зачем

Вкладка «Медиа» — исходная ключевая фича (см. `docs/features/00-functionality.md`, §4.5):
найти фото и видео **по всему устройству**, а не только в хранилищах, и потом что-то с
ними сделать (отправить, добавить в хранилище).

Подсистема крупная (скан → EXIF → превью → галерея), поэтому режем на срезы.
**Этот срез — только поиск:** обход файловой системы, классификация по типу, фильтры,
результат списком. Без EXIF, без превью, без постоянного каталога в БД.

## Границы среза

**Входит:**
- Классификация файла как фото/видео по расширению (`MediaKind`).
- Обход произвольной папки-корня с устойчивостью к недоступным подпапкам.
- Фильтры: тип (фото/видео), подстрока в имени, диапазон даты изменения, минимальный
  размер, ограничение количества результатов.
- Ленивое перечисление + `CancellationToken` — UI может остановиться, не дожидаясь
  конца обхода диска.
- Вкладка «Медиа» в UI: корень, фильтры, кнопка «Искать», список найденного.

**Не входит (следующие срезы):**
- EXIF (дата съёмки, GPS, ориентация) — поле `CapturedAt` заложено, но всегда `null`.
- Превью и сетка миниатюр.
- Постоянный индекс медиа в SQLite (сейчас скан «по запросу», как решено в §4.5 — v1
  это инструмент поиска-и-отправки).
- Действия «отправить» / «добавить в хранилище» — нужна разовая передача (пункт 4.2),
  её ещё нет.
- Системная галерея на мобильных (нужны разрешения и платформенные головы).

## Модель

```
MediaKind      = Photo | Video
MediaFile      = FullPath, FileName, Kind, Size, ModifiedAt, CapturedAt?
MediaQuery     = Kinds, NameContains, ModifiedFrom, ModifiedTo, MinSize, MaxResults
MediaScanner   = Scan(root, query, ignore, ct) -> IEnumerable<MediaFile>
```

`MediaFile` — не `FileIndexEntry`: у индексации другая задача (блоки, хэши, дельта),
у медиа — быстрый обзор без чтения содержимого. Поле `CapturedAt` — задел под EXIF,
чтобы вкладка доросла до галереи без переделки модели.

## Классификация

По расширению, регистронезависимо (в отличие от `IgnoreRules`, где регистрозависимость
нужна для детерминизма между устройствами; здесь — локальный поиск для человека).

- Фото: `jpg jpeg png gif bmp webp tiff tif heic heif avif raw dng cr2 nef arw orf rw2`
- Видео: `mp4 mov avi mkv webm m4v mpg mpeg wmv flv 3gp mts m2ts`

Список — единственная точка правды (`MediaTypes`), расширяется без изменения сканера.

## Обход

Обычный `Directory.EnumerateFiles(..., AllDirectories)` не годится: на настоящем
устройстве (домашняя папка macOS/Windows) он падает на первой же недоступной подпапке и
теряет весь результат. Поэтому ручная рекурсия стеком:

- недоступная папка (`UnauthorizedAccessException`, `DirectoryNotFoundException`,
  `IOException`) — **пропускается**, обход продолжается;
- символические ссылки на папки (`ReparsePoint`) не разворачиваются — защита от циклов;
- скрытые папки (имя с `.` или атрибут Hidden) пропускаются по умолчанию;
- дополнительно применяется `IgnoreRules` (переиспользуем из `Indexing`), если задан.

Перечисление ленивое: `MaxResults` реально обрывает обход, а не фильтрует готовый список.

## UI

Вкладка «Медиа»: поле корня (по умолчанию — домашняя папка пользователя), чекбоксы
«Фото» / «Видео», поле подстроки имени, кнопка «Искать» / «Стоп», строка статуса и
список результатов (имя, путь, размер, дата). Скан идёт в фоновом потоке
(`Task.Run`), результат отдаётся в UI-поток через `IUiDispatcher`.

Лимит по умолчанию — 500 результатов, чтобы список оставался отзывчивым; в статусе
честно пишем, что показаны первые N.

## Тесты

- Классификация: расширения фото/видео, регистр, неизвестное расширение.
- Скан: находит фото и видео во вложенных папках; фильтр по типу; по подстроке имени;
  по дате; по размеру; `MaxResults` обрывает обход; скрытые папки пропускаются;
  `IgnoreRules` учитываются; отмена по токену.
- View-модель: скан находит файлы во временной папке, фильтры прокидываются, статус
  заполняется, повторный запуск очищает прошлый результат.
