# Фича: передача блоков и сборка файла

**Статус:** готово — первая реальная синхронизация файла работает · **Слой:** `Porta.Core/Sync`, `Porta.Core/Protocol`

Готово: `BlockRequestMessage`/`BlockResponseMessage`/`BlockData`, `FolderBlockReader`,
`IBlockSource`/`MemoryBlockSource`/`CompositeBlockSource`, `FileAssembler` (проверка
хешей, атомарная запись, mtime, защита от traversal). 7 юнит-тестов + интеграционный
`File_is_synchronized_from_sender_to_receiver` поверх QUIC.

Завершает цепочку синхронизации: индекс → дельта ([08](08-index-exchange.md)) →
**передача недостающих блоков → сборка файла**. Это первая реальная синхронизация файла.

## Поток

1. Принимающая сторона по дельте знает недостающие блоки → шлёт `BlockRequestMessage`.
2. Отдающая сторона читает блоки из своих файлов по хешу (`FolderBlockReader`) → шлёт
   `BlockResponseMessage`.
3. Принимающая собирает файл из блоков (`FileAssembler`): свои имеющиеся блоки +
   полученные, в порядке `FileIndexEntry.Chunks`.

## Компоненты

### Сообщения
- `BlockRequestMessage(Hashes)` — какие блоки нужны.
- `BlockResponseMessage(Blocks)` где `BlockData(Hash, Data)`.

### FolderBlockReader (отдающая сторона)
Строит карту `хеш → (файл, смещение, длина)` из индекса; `TryGet(hash)` читает байты
блока из файла. Реализует `IBlockSource`.

### Источники блоков (`IBlockSource`)
- `MemoryBlockSource` — полученные блоки в памяти.
- `FolderBlockReader` — блоки из локальных файлов (дедупликация — переиспользуем то,
  что уже на диске).
- `CompositeBlockSource` — сначала одно, потом другое.

### FileAssembler (принимающая сторона)
Собирает файл по `FileIndexEntry`:
- для каждого блока берёт байты из `IBlockSource`, **проверяет длину и SHA-256**;
- пишет во временный файл, по завершении сверяет **контент-хеш всего файла**, затем
  атомарно перемещает на место;
- **сохраняет метаданные** (mtime из индекса);
- **защита от path traversal:** относительный путь из индекса не должен выводить за
  пределы папки хранилища (иначе отказ).

## Границы среза

- Запрос/передача блоков + сборка одного файла с проверками — **с тестами**.
- Оркестрация синхронизации целого хранилища (много файлов, порядок, прогресс,
  параллелизм), запись версий, удаления — следующие срезы (Этап 4).
- Backpressure/чанкованная передача очень больших блоков — позже.

## Безопасность

- **Проверка хешей** каждого блока и итогового файла — защита от повреждения/подмены.
- **Проверка пути** — защита от вредоносного относительного пути (выход за папку).
  Закрывает часть долга из рефлексии индексатора.

## Тесты

- `FolderBlockReader`: читает корректные байты блоков по хешу; неизвестный хеш → miss.
- `FileAssembler`: собирает файл из блоков идентично оригиналу; отвергает блок с
  неверным хешем; отвергает путь с `..` (traversal); сохраняет mtime.
- Локальный round-trip: скан файла → чтение его блоков → сборка копии → идентично.
- Интеграционно поверх QUIC: **полная синхронизация файла** — у отдающего есть файл,
  принимающий запрашивает блоки, собирает, содержимое совпадает.
