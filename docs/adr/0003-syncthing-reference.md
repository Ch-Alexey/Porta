# ADR-0003: Syncthing как архитектурный референс

- **Статус:** принято
- **Дата:** 2026-07-30

## Контекст

Porta по задаче близка к Syncthing — открытому P2P-инструменту синхронизации
файлов без центрального облака. Многие сложные задачи (безопасное связывание
устройств, обнаружение в сети, передача только изменившихся блоков,
версионирование, разрешение конфликтов) там уже решены и проверены годами.

## Решение

Используем Syncthing как **референс, а не зависимость**. Изучаем и адаптируем его
идеи, реализуя своё на .NET.

Что берём на вооружение:

- **Идентификация устройства** — публичный ключ как Device ID; доверие через
  обмен ключами (в нашем случае — QR/ссылка), без паролей и аккаунтов.
- **Block Exchange Protocol (BEP)** — принцип: файл делится на блоки, обмен идёт
  индексами блоков и хешами, передаются только недостающие блоки.
- **Версионирование** — сохранение предыдущих версий изменённых файлов.
- **Разрешение конфликтов** — через version vectors, а не «последний победил».

Чего **не** копируем на старте:

- Глобальный discovery-сервер и relay-инфраструктуру (это про «другие сети» —
  отдельный поздний этап).
- Полную совместимость с протоколом Syncthing (нам не нужна интероперабельность
  с ним; свой протокол проще и гибче).
