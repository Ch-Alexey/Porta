# CLAUDE.md — точка входа для агента

Это онбординг для ИИ-агента, впервые открывающего проект **Porta**. Прочитай целиком,
потом переходи к `docs/`.

## Что это

Кроссплатформенное P2P-приложение на .NET 10 для синхронизации файлов между устройствами
напрямую, без облака (аналог Dropbox). Стек и решения зафиксированы в ADR (`docs/adr/`).

## Язык и стиль работы (ВАЖНО — так принято в проекте)

- **Общение и вся документация — на русском.**
- **Документация-до-кода:** перед реализацией фичи пишется контекст в `docs/features/NN-<name>.md`
  (что и зачем), потом код **с тестами**. Крупные решения → ADR в `docs/adr/`.
- **Рефлексия после каждого этапа:** честный самоанализ в `docs/reflections/NN-<name>.md`
  (что сделал, что хорошо, техдолг явно, на что смотреть). Тон честный, не «всё отлично».
- **Каждый срез заканчиваем зелёными тестами и чистой сборкой** (0 предупреждений — держим планку).
- После значимого куска предлагаем пользователю **сообщение коммита** (коммитит он сам).
  Периодически проверяем уязвимости: `dotnet list Porta.slnx package --vulnerable --include-transitive`.

## Структура решения

`Porta.slnx` (новый XML-формат solution, .NET 10). Central Package Management —
`Directory.Packages.props` (версии пакетов там, в `.csproj` только имена).

- `src/Porta.Core` — **ядро, платформонезависимое.** Identity, Data (SQLite),
  Indexing (скан + content-defined chunking + IgnoreRules), Pairing, Discovery
  (абстракции), Protocol (MessagePack-сообщения, PeerSession), Transport (абстракции +
  сертификат), Sync (дельта, блоки, версии, конфликты, движки), Media (поиск фото/видео
  по устройству), App (AppEnvironment/IAppData).
- `src/Porta.Infrastructure` — реализации сетевых абстракций: mDNS (Makaretu.Dns),
  QUIC-транспорт (System.Net.Quic).
- `src/Porta.App` — общий UI на Avalonia (MVVM, CommunityToolkit.Mvvm).
- `src/Porta.App.Desktop` — десктоп-голова + composition root (создаёт QUIC/mDNS,
  внедряет в App через `App.Injected*`).
- `src/Porta.App.{Android,iOS,Browser}` — головы на диске, **не в solution** (нужны workloads).
- `tests/Porta.Core.Tests`, `tests/Porta.Infrastructure.Tests` (интеграционные, `[Trait("Category","Integration")]`),
  `tests/Porta.App.Tests` (view-модели).

## Сборка и тесты

```bash
dotnet build Porta.slnx
dotnet test Porta.slnx
```

- **libmsquic (QUIC):** `Directory.Build.targets` копирует `libmsquic.dylib` из Homebrew в
  вывод сборки на macOS — тесты QUIC и приложение работают **без** `DYLD_LIBRARY_PATH`.
  Если QUIC недоступен, интеграционные тесты тихо пропускаются (гейт `QuicTransport.IsSupported`).
- CI (`.github/workflows/ci.yml`, ubuntu) гоняет только юниты: `--filter "Category!=Integration"`
  (на раннере нет multicast/libmsquic).
- Запуск приложения: `dotnet run --project src/Porta.App.Desktop`.

## Что уже готово (на 2026-09-06, 254 теста)

Полное ядро синхронизации + базовый UI:
- Личность (ECDSA P-256, Device ID), персистентность (SQLite + миграции), индексация с CDC,
  игнор-паттерны.
- Связывание (pairing по токену QR/ссылки, доменно-разделённые подписи).
- Обнаружение по mDNS; транспорт QUIC + TLS 1.3 с pinning по Device ID; сессии + доверие из БД.
- Дельта-синк (только изменившиеся блоки), версионирование (не терять данные), version vectors,
  разрешение конфликтов (обе версии), персистентный версионированный индекс.
- UI на Avalonia: Device ID, вкладки «Хранилища» (список+добавление + выборочный доступ:
  поделиться папкой с устройством), «Устройства» (доверенные + найденные в сети +
  связывание по токену + кнопка «Синхронизировать») и «Медиа» (поиск фото/видео по
  устройству: корень, тип, имя; без EXIF и превью). Синк касается только расшаренных хранилищ.
- **Потоковая отдача блоков:** блоки идут пачками (бюджет 4 МиБ), принятые складываются
  на диск (`SpooledBlockSource`), у чтения есть таймаут (`MessageChannel.IdleTimeout`).
  Синк больше не ограничен размером сообщения и не виснет на мёртвом пире.
  См. `docs/features/27-block-streaming.md`.
- **Разовая передача (ядро):** намерение сессии (Sync/Drop), потоковая передача файлов с
  подтверждением получателя (`IDropAcceptance`). UI ещё нет — входящие передачи пока
  отклоняются. См. `docs/features/26-drop-transfer.md`.
- **Авто-синхронизация** при появлении доверенного устройства **и при локальных изменениях
  файлов** (FileSystemWatcher). Фоновый QUIC-приём.
- Сквозные интеграционные тесты: discover→sync и авто-синк на реальном mDNS+QUIC.

Полный список — в `docs/roadmap.md` (галочки) и `docs/features/00-functionality.md`
(функциональная картина).

## Чего НЕ хватает (ближайшие кандидаты)

1. **UI разовой передачи** (ядро готово, срез 27): вкладка «Отправить», диалог
   «Принять файлы от устройства A?», папка «Загрузки» в настройках.
2. **Переинициализация `FileSystemChangeNotifier` при изменении списка хранилищ** (сейчас
   наблюдает только те, что были на старте — новое хранилище подхватится после перезапуска).
   Небольшой срез: канал «список хранилищ изменился» от VM к голове. Тогда же — тумблер
   per-link auto/manual (сейчас «поделился = авто-синк»).
3. **Двусторонняя конвергенция за сеанс** (сейчас — независимые pull; долг с Этапа 4).
4. **Медиа — продолжение** (срез 1 «поиск» готов, см. `docs/features/25-media-scan.md`):
   EXIF (`MediaFile.CapturedAt` пока всегда `null`, сортировка идёт по дате файла),
   превью/сетка, стриминг результатов пачками, действие «отправить» (ядро передачи уже
   есть — ждёт UI из п.1).
5. **Поставка libmsquic** для конечного пользователя (bundle/установщик; сейчас через Homebrew),
   мобильные головы, защищённое хранилище ключа устройства (сейчас файл 0600).

**Известные пределы (не дефекты, но знать надо):** `BlockRequestMessage` и
версионированный индекс — по-прежнему одно сообщение, поэтому за один синк проходит
~3.8 ГБ *новых* данных; сверх этого обе стороны падают громко (не виснут). Ранний
движок `SyncProtocol` не используется приложением и содержит старый дефект —
кандидат на удаление.

## Как продолжать

1. Прочитай `docs/README.md`, `docs/roadmap.md`, свежие `docs/reflections/` (там честный техдолг).
2. Выбери срез, напиши `docs/features/NN-*.md`, реализуй с тестами, прогони сборку/тесты,
   напиши `docs/reflections/NN-*.md`, предложи коммит.
3. Держи слои: ядро не зависит от инфраструктуры/UI; сетевое — за абстракциями.

Память проекта (авто-загружается): `porta-project.md` (стек/решения/прогресс),
`reflection-after-stages.md` (правило рефлексий).
